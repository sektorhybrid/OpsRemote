# What's new

Back to the [README](../README.md). Each version's details are in [Features](features.md).

## 0.6.2

- **Mouse & clipboard, the same everywhere:** a new tab, **Preferences → Workspace → Mouse & clipboard**, holds everything about selecting, copying and pasting with the mouse, and it applies to terminals and to every text field in OpsRemote (search box, file names, settings, editors) alike, on Linux and Windows. **Paste** decides what every paste gives (middle-click, right-click, Ctrl+Shift+V, the menu): **the newest** of your last selection in OpsRemote and your last copy in any program (the default), always the clipboard, or the system standard (on Linux middle-click pastes the selection). **Double-click selects** words with extra characters (`:@-./_~?&=%+#` by default, so paths, addresses and `user@host` are one word) or letters and digits only. Copy on select is now one setting for both systems (on), and never copies from password fields. Middle-click closing a tab and the mouse wheel over drop-down lists moved here too. Saved terminal sessions get a **Copy and paste** card (Appearance tab) with Links and, new, Confirm multi-line paste for that session.
- **Drop files on a terminal to upload them:** on local terminals (Linux) and SSH tabs, files and folders dropped on a terminal go into the folder of the program running in it, found the moment you drop them (not a remembered folder). OpsRemote asks first, naming the files and the folder, and warns when another program is in front (for example `ssh other-server`, `su`, `sudo -i`, or an editor): the files would not go where that program is. **Choose Another Folder…** and **Paste the Paths** are always offered; Shift while dropping types the paths as before. Files already there follow **When a file already exists**; anything that went wrong is shown in a message. **Preferences → Terminals → Behaviour → Upload files dropped on a terminal** (on by default) and each session's **Copy and paste** card turn it off. On an SSH tab the server is asked at that moment, over the same connection, which program is in front and where (Linux servers that accept the `LC_*` variables OpenSSH servers usually do; otherwise the folder the shell last reported, said as such), and the files go through the Files panel's upload, with its progress. Other terminals (Docker, Kubernetes, WSL, Telnet, Rlogin, serial, Mosh) type the paths, as before.
- **Session settings in cards:** the protocol tabs of the session window (SSH, RDP, VNC, FTP, Rlogin/RSH, XDMCP) group settings in light cards, the same in every session type: **General** (with reconnecting), **Logon** (keys, certificates, Kerberos, security), then the type's own (Terminal, Start program, RD Gateway, Listening, Repeater, Sound, Devices…). In each card the fields come first, then the switches that stand alone; labels are shorter, the label column has the same width from tab to tab, and the ↺ button sits in front of the field.
- **Network tab:** Jump host, Proxy, Port forwarding and Wake-on-LAN are cards of one Network tab (each shown for the session types it applies to), so an SSH session has 5 tabs instead of 7; the tab scrolls when it is taller than the window. Big lists (port forwarding, automation tables, trusted RDP certificates, backups) show 5 rows and scroll for more, instead of growing with the window.
- **Preferences → Terminals:** the category is now called Terminals (its settings are for every terminal, as Connections is for every connection).
- **Dropping files onto a remote desktop (Wayland):** files dropped onto an RDP session stayed on the remote clipboard only until OpsRemote got the focus back, when it sent the local clipboard again; Ctrl+V in a remote folder then pasted nothing (Windows played its sound). The dropped files now stay offered until you really copy something else; your own clipboard is not touched.
- **Choosing the editor no longer freezes:** **Browse…** for the remote-file editor (Network → Files & transfers) opened in a folder such as `/usr/bin` and OpsRemote stopped answering for about ten seconds while the file window worked out the type of every file; types now come from the name (Program, Folder, PY file…), in every file and folder window of OpsRemote (keys, downloads, uploads, logs, scripts, imports…). The list above the field also shows the program in use (for example VSCodium for `/usr/bin/codium`) instead of going back to "Choose a program…".
- **Links in Preferences go to the setting:** a row that points to another place (for example "Connections → RDP" in Mouse & clipboard) now opens that tab, scrolls to the settings it means and tints them for a moment. Mouse & clipboard has a **Remote desktops clipboard & file transfers** card: the RDP and VNC clipboard settings, and copying files in the Files panel (Network → Files & transfers).
- **Settings moved, values kept:** the settings above moved from `behaviour` and `startup` to `mouse_clipboard` in `settings.yaml` (settings step 5, after a backup). Every value set by hand is kept; copy on select is on if it was on for either system; a middle-click set to "Paste clipboard" becomes Paste with the rule "Always the clipboard". One change in behaviour: on Linux, middle-click "Paste selection" now follows the rule, so by default it pastes the newest of your last OpsRemote selection and your last copy.
- **Titles with "&":** headings, tabs and cards use "&" instead of "and" (for example **Startup & exit**, **Security & vault**, **Data & backup**).
- **Inactive buttons look inactive:** buttons that cannot be clicked now have faded text in every look, Kvantum themes included (several dark themes drew them like active ones).
- **Clearer look buttons:** "Save into \"name\"…" is now **Save into Selected Look…** (one width whatever the name; the confirmation names the look), and "Back to \"name\"" is now **Revert Unsaved Changes**, with the look it goes back to in its tooltip. It now works after any change by hand and after a restart: the look the appearance came from is kept in the settings (`ui.base_look`), and at the first start the matching look is taken.
- **Interface font follows at once:** changing the interface font or its size in Preferences now updates every open window right away; some text (rows, buttons, lists under a style) used to keep the old size until the look was saved.
- **Copy on select works:** before, it never copied anything. It now copies once, when you finish selecting (mouse released, a word by double-click, a line by triple-click). It is on by default (like PuTTY), so every way of pasting gives the same text after a selection; see Mouse & clipboard below. A setting turned on by hand before stays on.
- **Edit before pasting:** the window that asks before several lines are pasted (or sent from the Commands tab) has **Edit the text**: change the text there, and what you edited is pasted. **Workspace → Mouse & clipboard → Start in editing mode** opens it editable every time.
- **Self-repairing program files:** no more "This copy of OpsRemote is incomplete" after an abrupt exit. The program's unpacked copy in `runtime/` now carries a list of its files, checked at each start. A copy that lost files (removing it was cut short, an antivirus or cleaner took some) is deleted and unpacked again on its own, in a few seconds; on Windows, while another OpsRemote still runs from it, only the missing files are filled in. Your sessions and settings are never in that folder.
- **One multi-line confirmation:** **Workspace → Mouse & clipboard → Confirm multi-line paste** now also covers commands of several lines sent from the Commands tab, which had a toggle of its own. It stays on unless you had turned off both.
- **Clearer start-up messages:** when OpsRemote really cannot start (its own package files are missing, the disk is full, its folder is read-only, Windows is too old), the message says what happened and why, that your sessions and settings are unaffected, and what to do.
- **One setting for links:** **Workspace → Mouse & clipboard → Links in terminal output**: open with Ctrl+click or the menu, from the menu only, or off. It replaces "Enable terminal links" and "Ctrl+click opens links"; your choice carries over.
- **Session name with user@host:** tabs can be titled "Session name (user@host)" (**Workspace → Tabs → Tab title**).
- **Padding applies at once:** changing the terminal padding updates open terminals, not only new ones.
- **Keyring works on newer Linux:** the system keyring (libsecret) failed to load on distributions newer than the package's base, such as Arch; OpsRemote now brings its own copy.
- **Reconnect settings for every type:** SSH, RDP and VNC each have Reconnect automatically, Wait before reconnecting and Tries (0 keeps trying) in their Preferences tab and in each session. RDP and VNC used to stop after 6 fixed tries.
- **Kerberos logon order:** **Security & vault → Kerberos → Sequence of authentication**: Kerberos first (as before), after keys, or last; sessions can choose their own.
- **Preview before copying passwords:** copying saved passwords between the vault and the system store first shows what is new, the same, or different; a different one is replaced only if you tick it. Passwords are never shown.
- **Incomplete proxy caught:** a proxy chosen without host or port is marked in red with the reason; Save waits until it is complete. Before, it silently connected without a proxy.
- **Choose the editor from a list:** **Network → Files & transfers → Editor** lists the text editors found on this computer, has Browse…, and says whether the program is there.
- **Clear inherited values:** in a session's settings, a row you changed gets a small ↺ button back to the inherited value (it can be turned off: **Appearance → Session list → Session settings windows**); its tooltip says "Revert to default". Fields show the inherited value as it is, without a "Default (…)" label, and drop-downs list it only once. In every session type's window and the folder's Kerberos tab.
- **One tab order for every session type:** Connection · Display or Appearance · Local resources · Automation · Network. RDP and VNC now open on Connection, and the serial line's tab is called Connection.
- **File-only SFTP and SCP sessions** no longer show terminal settings (Terminal type, Backspace, Forward X11, Files follow folder).
- **Local and container sessions** group their settings in General, Logon and Start cards; Logon only when there is something to log on with. User and Start folder say "As the distribution or image sets it" instead of "Default".
- **Proxy note** names the session's protocol (it said "SSH connections" for RDP, VNC and FTP too).
- **Settings updated automatically:** when a setting changes its place or form (as Copy on select did), OpsRemote converts your `settings.yaml` once, after backing up the settings folder (restorable in **Preferences → Data & backup**). A choice you made carries over; settings from a newer OpsRemote are left as they are.

## 0.6.1

- **Pasting several lines:** the confirmation (terminal paste and **Commands**) is a resizable window that shows the whole text in a fixed-width font, with its line count. It keeps its size until OpsRemote is closed.
- **Tabs with new output** are marked again with every look: before, the OpsRemote style and the Kvantum styles drew over the title's colour. The mark is now a softly pulsing dot beside the title (or a steady dot, or the title's colour, or off); each tab keeps room for it, so tabs do not move when one is marked. Its dot colour and pulse colour are Automatic (from the look, chosen to stand out against the tab bar) or Custom (**Preferences → Workspace → Tabs → Activity in background tabs**).

## 0.6.0

**Logging on**
- **SSH certificates:** a key's OpenSSH certificate (`key-cert.pub`) is sent with it, or a certificate chosen per session. The session window shows who it is for and until when, in red when it has expired or is for another user.
- **FIDO2 security keys** (`sk-ed25519`, `sk-ecdsa`; YubiKey, Windows Hello): logging on with a touch and, when the key needs it, its PIN. **Tools → SSH Keys** creates them (optionally kept on the key) and copies the keys kept on a security key.
- **Kerberos (GSSAPI)** on Linux: logging on with your domain ticket, optionally passing it on (`ssh -K`), for everything, a folder, or a session; Preferences show the ticket and run `kinit`.

**Automation**
- **Login scripts and triggers** (a session's or folder's **Automation** tab): wait for a text, then type an answer; watch the output and type, notify, beep, or mark the tab.
- **Saved scripts** (**Tools → Scripts**, kept in `settings/scripts/`): run whole on a server, in a tab, on many hosts, after logging on, or inside a container; with an interpreter, optional `sudo`, and `{fields}` asked for when they run.
- **Commands** and **Scripts** tabs beside Sessions and Files, with search and groups; **View** shows or hides each tab.

**New session types**
- **Local**: a shell of this computer (PowerShell, PowerShell 7, Command Prompt, Git Bash; bash, zsh, fish…) or any program, with **Run as administrator** (Windows UAC, Windows sudo; Linux sudo or pkexec).
- **WSL** (Windows): a chosen distribution, user and folder.
- **Container (Docker)**: a shell in a container, here, through a Docker context, on a remote engine over TCP with TLS, or on an SSH server; Podman too. **Open a Container…** on SSH sessions.
- **Container (Kubernetes)**: a shell in a pod, with the default kubeconfig, a saved credential, a kubeconfig file, a token, or a client certificate. **Tools → Kubernetes Credentials** keeps kubeconfigs encrypted or as private files.
- Their lists (distributions, containers, contexts, namespaces, pods) fill themselves, with their state on a line under each.

**Preferences**
- New categories: **Connections** has one tab per session type; **Network** (proxy, files and transfers), **Security and vault** (now with keys and certificates, Kerberos) and **Tools** (Run on hosts, HTTP requests, scripts).
- Every main feature can be turned off.
- Each session window opens on its protocol's own tab.

**Under the hood**
- libssh 0.12.2 in both packages (built from its signed release), with libfido2 and libcbor on Windows and MIT Kerberos on Linux.
