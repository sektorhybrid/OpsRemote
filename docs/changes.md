# What's new

Back to the [README](../README.md). Each version's details are in [Features](features.md).

## Next

- **Remote desktop security fixes:** the bundled FreeRDP is now 3.33.1, which fixes 22 security advisories. With the old version, a malicious or compromised RDP server could crash OpsRemote or corrupt its memory, for example through drawing orders, the Progressive codec or the smart-card channel.
- **VNC security fixes:** three fixes from LibVNC's developers are now built in. They are not in any LibVNC release yet, so we apply them to 0.9.15 ourselves. A malicious VNC server could write past the screen's memory through the Tight and UltraZip formats, and this was possible with every quality setting, **Best** included.
- **Downloads without HTTP/2:** **Network Tools** downloads now always use HTTP/1.1. Qt's HTTP/2 support has a flaw a server can trigger, and a single download gains nothing from HTTP/2.
- **Linux Qt security fixes:** the Linux package now carries Qt's published fixes for this year's Qt security issues (a web server's `Cache-Control` header read past its end, NTLM log-ons, HTTP/2 uploads, and XML files that could exhaust memory or time). AlmaLinux, whose Qt the Linux package uses, has not shipped them yet, so we rebuild its Qt with them.
- **Up-to-date system libraries:** both packages are now built with their build systems' latest security updates (AlmaLinux 9 and Fedora 45; before, the build images kept the libraries they first had), and the Windows FIDO2 support uses libcbor 0.14.1.
- **Newer Windows base:** the Windows program is now built on Fedora 45 (supported until December 2027), with Qt 6.11.2 and OpenSSL 3.5.9, the long-term-support release, built by us. The previous build base no longer received security updates, and its OpenSSL (3.2.4) was out of date. Your settings stay compatible between Linux and Windows.

- **Windows fit the screen:** every window opens within the screen's free area, and the session windows (SSH Connection and Automation, Appearance, RDP and VNC tabs…) scroll when the screen is too small for them, so **Save** stays in reach and the window can always be resized. Before, the Edit Saved Session window could be taller than a laptop screen and impossible to make smaller. On large screens nothing changes.
- **Preferences opens without waiting:** checks for things OpsRemote may need from this computer (an X server, docker or kubectl, WSL, Kerberos, security keys) now run in the background, so Preferences and the session window open at once; a note appears when something is missing. On Windows, looking for an X server could hold up each opening for a third of a second.
- **No program files left behind:** the unpacked program in `runtime/` is now removed when OpsRemote closes by default, and also after a crash or after it was ended by force (before, only on a normal close, and only with the setting on). A copy left behind anyway is checked at the next start and repaired without asking. **Preferences → Data & backup → Remove the unpacked program when closing** off keeps it for quicker starts. Earlier versions saved this setting as off without asking, so it is switched on once (turn it off again if you prefer quicker starts); your other settings are unaffected.
- **Remote desktops get what you picked last:** RDP and VNC tabs now share whatever a paste in OpsRemote would paste: the last copy in any program, or text you only selected in an OpsRemote terminal or field (and, on Linux with that option on, in other programs). Before, with **Copy on select** off, a selection pasted in OpsRemote's terminals but not inside a remote desktop. **Share clipboard text** still turns it off per session.
- **Side panel tabs always in view:** the side panel is never narrower than its tabs (Sessions, Files, Commands, Scripts), whatever the look, font or **Always fit the panel to the list** setting; before, with that setting off, a remembered width could hide the last tabs behind scroll arrows.
- **Taskbar icon on Linux:** the taskbar and dock now show OpsRemote's icon instead of a gear. OpsRemote keeps a hidden launcher entry for itself in your desktop's applications folder (not listed in menus), only when that folder exists and can be written to; **Preferences → Workspace → Startup & exit → Show the OpsRemote icon in the taskbar** (on by default) turns it off and removes the entry.

- **No more odd characters on clicks:** after a program such as vim, htop or tmux ended badly (a dropped connection, a killed program), clicking in the terminal could type characters like `^[[M !!` into the shell. Now a session that ends or reconnects switches off what such a program left on, the terminal's right-click menu has **Reset Terminal** for other cases (the text stays), and the `reset` command also stops focus reports, which it left on before.
- **Move handle on pane bars:** every terminal's bar now has a handle at its left end (six dots, lit up under the pointer, with a tooltip), so it shows that the terminal can be dragged to another place, another tab or a tab of its own. The pointer is an open hand wherever a press on the bar drags it.
- **Panes settings page:** **Preferences → Workspace → Panes** has the pane bar's settings (moved from Tabs, your choices kept) and a new **Moving terminals** card: switch moving off, drag only by the handle, let a click on the handle open the Move menu, stop tabs being pulled out of the tab strip, and choose whether (and after how long, 500 ms by default) a tab held over opens. The defaults work as before.
- **Move menu:** the terminal's right-click menu has **Move ▸**: Move to a New Tab, Move Next To ▸ another tab, and Pick Up and Move (the terminal follows the pointer until a click drops it; a right click or Esc cancels), for moving without holding the mouse button.
- **Pane bar parts stay in place:** the message and the transfer each keep their own part of the pane bar, between dividers, so the message no longer gets shorter when a transfer starts (**Parts of the bar**: Fixed, the default, or Only when used, as before). On narrow panes the message keeps about 12 characters. Hovering the message shows it whole; it no longer says "Click for this tab's messages", which did nothing there.

## 0.6.5

- **Closing no longer crashes:** closing OpsRemote with tabs open could end in "OpsRemote crashed" right after the window went away (Linux and Windows, from the new pane bars). Your settings were kept.
- **Remote desktop pastes no longer get stuck:** files copied here and pasted on the remote computer showed as a transfer that never ended when Windows gave up halfway ("unspecified error"). Now such a paste ends as failed, with the reason in the pane's bar, when the remote computer stops asking for the files for 30 seconds, takes a clipboard of its own, gets a new copy from here, or disconnects; and it has ✕ to stop it from here. Focusing OpsRemote's window (on Wayland) no longer announces the same clipboard to the server again, which could break a paste under way.
- **Move terminals by dragging:** drag a terminal by its pane bar onto another pane, as in Terminator: the half of the pane where it will go is coloured (left, right, top or bottom) and a small picture of the terminal follows the pointer. Let go on a pane's half to split there, on a tab to go beside its active pane (held over a tab for a moment, it opens), or on the tab strip past the tabs to give it a tab of its own. Pull a tab down out of the tab strip to drag it whole: a split tab keeps its arrangement. With no pane bar (**Off**, or **Only when needed** with nothing to show), a grip appears when the pointer rests at a terminal's top edge. Esc cancels; remote desktops and file tabs stay where they are.
- **Same file, asked first:** starting an upload or download of a file (or folder) that another transfer is writing right now, in this tab or another, asks what to do: **Wait for It** (starts when the other has ended; then you are asked whether to overwrite), **Save Under a New Name** (`name (1).ext`; greyed out for folders, which are merged into), **Stop It, Start This** (cancels only the other one) or **Don't Start**. A waiting transfer shows in **Transfers** with ✕.
- **Cancel stops one transfer:** ✕ on a transfer stops only that one; the transfers queued after it in the same tab go on (before, they were cancelled too, though the list did not show them).
- **Pane bar keeps its room:** a pane bar that changes height (a new look or interface font) moves its terminal again, so it no longer covers the last line; and every pane bar takes a new interface font (one of them could keep the old, smaller one).
- **Two uploads of one file:** two uploads of the same file to the same place (from two tabs, or a split pane of the same session) no longer write into one temporary `name.filepart`: each upload has its own (`name.xxxxxx.filepart`). Before, the second one failed with "Could not replace …: no such file or folder", and the file could arrive mixed from both.
- **Pause and retry transfers:** in the Transfers lists, a file transfer (SFTP, SCP, FTP) has ⏸ **Pause** and ✕ **Cancel** while it runs; paused, ⏸ becomes ▶ **Continue** (the connection and the file stay open). Once cancelled or failed, ✕ becomes ↻ **Retry**, which starts it again from the beginning, also after reconnecting. Files opened for editing, remote-desktop copies and Network Tools downloads keep only ✕.
- **Side panel off the window's edge:** the side panel (its tabs, the search box and the session list) keeps a small gap from the window's left edge, as wide as the one between the panel and the tabs; it used to touch the edge. Its tabs and search box start exactly where the session list's box does, at any width.
- **Close tabs to one side:** a tab's right-click menu has **Close Tabs to the Left** and **Close Tabs to the Right**, next to Close Other Tabs.
- **Lists take over while open:** while the Messages or Transfers list is open, the rest of the window waits, as with a modal window: the pointer, the wheel, keys and shortcuts don't reach the session under it (a remote desktop shows no rollovers). Esc or a click outside closes the list; that click does nothing else.
- **Solid lists:** the Messages and Transfers lists are solid by default, also with looks whose colours are see-through (the remote desktop showed through them). **Preferences → Appearance → Looks → See-through lists** makes them a little see-through in every look; it is part of each look.
- **Rounded corners:** the tabs and the session list have softly rounded corners, whatever they show: a terminal, a remote desktop or VNC screen. **Preferences → Appearance → Looks → Rounded corners** sets how round: Square, 2, 4, 6 (the default), 8 or 10 px. It is part of each look; the built-in Classic look stays square. Your saved looks get 6 px.
- **Double-click to fit the side panel:** a double-click on the edge between the side panel and the tabs makes the panel as wide as what it shows: the session list, or the files listed in the Files tab. With nothing listed, it stays as it is. Up to half the window, as with **Always fit the panel to the list**.
- **Fewer words in the pane bars:** tabs no longer report what you can see anyway ("Connected to …", "Copying…", "Uploading … (see the Files panel)", "Recording this tab", a port forward listening, Files following the folder). When a tab connects again, its earlier disconnect message is put away (still in the tab's list).
- **Fitting the side panel keeps all its tabs:** with **Always fit the panel to the list**, the side panel is also at least as wide as its Sessions, Files, Commands and Scripts tabs, so they all show without the ‹ › scroll buttons.
- **Files panel looks the same without files:** when the current tab has no files to show (or no tab is open), the Files side panel keeps its usual look (title, buttons, the list with its columns) with the reason in the middle of the empty list, instead of a plain grey area. "Connecting…" and "Disconnected." show the same way. Sync Folders is greyed out while there is no connection.
- **Transfer list after a cancel:** a cancelled or failed transfer loses its ✕ at once in an open Transfers list (before, the ✕ stayed until the list was opened again), and the list no longer shrinks to almost nothing when a transfer ends while it is open.
- **All transfers in one place:** file transfers of every kind (the Files panel and file sessions over SFTP, SCP and FTP, files dropped on a terminal, remote-desktop clipboard copies, Network Tools downloads) show their progress in its pane's bar (file, bar, %, "+N" for more, ✕ to cancel) and in a **Transfers** list at the bottom right (**Transfers · 2 · 45%**) with every tab's transfers, their speed, and **Clear done**. The Files panel no longer has its own progress area at the bottom, and the remote-desktop bar only offers **Save to…** and **Open folder**. Downloads started by Sync Folders were shown as uploads; they now show the right way.
- **Lists open inside the window:** the Messages and Transfers lists open just above their buttons, lined up with the window's right edge, and close with a click elsewhere or Esc, the same on Linux (also Wayland) and Windows.
- **A bar on every pane:** each terminal and remote screen, and each pane of a split tab, has a bar with what it has to tell you: a question with its buttons (**Reconnect** / **Close Tab** after a session ended, **Reconnect** in file sessions, the remote desktop's **Save to…** / **Open folder** / **Not now**), else its newest message (a script that could not run, a recording started), and its transfer on the right (✕ cancels a running one; a finished one shows a few seconds, a failed or cancelled one until ✕). A question stays until answered, a warning until ✕, a notice goes after 8 seconds in view. **Preferences → Workspace → Tabs → Pane bar** puts it at the Top (default) or Bottom, or Off (questions then show inside the tab), and **Show the pane bar**: **Always shown** (default: every pane keeps its bar, empty when there is nothing to say, so nothing ever moves) or **Only when needed** (the bar comes and goes; it pushes a terminal down and covers the top edge of a remote screen, which keeps its size). The bar is flat, a shade between the window's colour and the colour of lists.
- **Messages you can read again:** notices and warnings (a session that could not open, a script that could not be sent, the vault locking itself) no longer flash by in the status bar for a few seconds. A **Messages** button at the bottom right shows how many are new ("Messages · 3 new", in the accent colour when there are any); click it to read them in full, with the time, and **Clear all**, in a list with rounded corners. Simple confirmations such as "Saved session" are no longer shown, and the bottom left of the window stays free. Next to it, a **Transfers** button has its place for the transfers coming next. Every message a pane shows also goes there, with its tab (and pane) name.
- **Preferences opens without flashes:** on Windows, opening Preferences the first time showed a few small empty windows for a moment, one for each container program that is not installed (docker, podman, kubectl); its "not installed" notes now appear only in their page.
- **Script message on Windows:** running a saved script in a tab that cannot run it said "Scripts run in connected SSH tabs (and local terminals)", but local terminals on Windows cannot run them yet; on Windows it now says only SSH tabs.

## 0.6.2

- **Mouse & clipboard, the same everywhere:** a new tab, **Preferences → Workspace → Mouse & clipboard**, holds everything about selecting, copying and pasting with the mouse, and it applies to terminals and to every text field in OpsRemote (search box, file names, settings, editors) alike, on Linux and Windows. **Paste** decides what every paste gives (middle-click, right-click, Ctrl+Shift+V, the menu): **the newest** of your last selection in OpsRemote and your last copy in any program (the default), always the clipboard, or the system standard (on Linux middle-click pastes the selection). **Double-click selects** words with extra characters (`:@-./_~?&=%+#` by default, so paths, addresses and `user@host` are one word) or letters and digits only. Copy on select is now one setting for both systems (on), and never copies from password fields. Middle-click closing a tab and the mouse wheel over drop-down lists moved here too. Saved terminal sessions get a **Copy and paste** card (Appearance tab) with Links and, new, Confirm multi-line paste for that session.
- **Drop files on a terminal to upload them:** on local terminals (Linux) and SSH tabs, files and folders dropped on a terminal go into the folder of the program running in it, found the moment you drop them (not a remembered folder). OpsRemote asks first, naming the files and the folder, and warns when another program is in front (for example `ssh other-server`, `su`, `sudo -i`, or an editor): the files would not go where that program is. **Choose Another Folder…** and **Paste the Paths** are always offered; Shift while dropping types the paths as before. Files already there follow **When a file already exists**; anything that went wrong is shown in a message. **Preferences → Terminals → Behaviour → Upload files dropped on a terminal** (on by default) and each session's **Copy and paste** card turn it off. On an SSH tab the server is asked at that moment, over the same connection, which program is in front and where (Linux servers that accept the `LC_*` variables OpenSSH servers usually do; otherwise the folder the shell last reported, said as such), and the files go through the Files panel's upload, with its progress. Other terminals (Docker, Kubernetes, WSL, Telnet, Rlogin, serial, Mosh) type the paths, as before.
- **Session settings in cards:** the protocol tabs of the session window (SSH, RDP, VNC, FTP, Rlogin/RSH, XDMCP) group settings in light cards, the same in every session type: **General** (with reconnecting), **Logon** (keys, certificates, Kerberos, security), then the type's own (Terminal, Start program, RD Gateway, Listening, Repeater, Sound, Devices…). In each card the fields come first, then the switches that stand alone; labels are shorter, the label column has the same width from tab to tab, and the ↺ button sits in front of the field.
- **Network tab:** Jump host, Proxy, Port forwarding and Wake-on-LAN are cards of one Network tab (each shown for the session types it applies to), so an SSH session has 5 tabs instead of 7; the tab scrolls when it is taller than the window. Big lists (port forwarding, automation tables, trusted RDP certificates, backups) show 5 rows and scroll for more, instead of growing with the window.
- **Preferences → Terminals:** the category is now called Terminals (its settings are for every terminal, as Connections is for every connection).
- **Dropping files onto a remote desktop (Wayland):** files dropped onto an RDP session stayed on the remote clipboard only until OpsRemote got the focus back, when it sent the local clipboard again; Ctrl+V in a remote folder then pasted nothing (Windows played its sound). The dropped files now stay offered until you really copy something else; your own clipboard is not touched.
- **Choosing the editor no longer freezes:** **Browse…** for the remote-file editor (Network → Files & transfers) opened in a folder such as `/usr/bin` and OpsRemote stopped answering for about ten seconds while the file window worked out the type of every file; types now come from the name (Program, Folder, PY file…), in every file and folder window of OpsRemote (keys, downloads, uploads, logs, scripts, imports…). The list above the field also shows the program in use (for example VSCodium for `/usr/bin/codium`) instead of going back to "Choose a program…".
- **Links in Preferences go to the setting:** a row that points to another place (for example "Connections → RDP" in Mouse & clipboard) now opens that tab, scrolls to the settings it means and tints them for a moment. Mouse & clipboard has a **Remote desktops clipboard & file transfers** card: the RDP and VNC clipboard settings, and copying files in the Files panel (Network → Files & transfers).
- **Settings moved, values kept:** the settings above moved from `behaviour` and `startup` to `mouse_clipboard` in `settings.yaml` (settings step 5, after a backup). Every value set by hand is kept; copy on select is on if it was on for either system; a middle-click set to "Paste clipboard" becomes Paste with the rule "Always the clipboard". One change in behaviour: on Linux, middle-click "Paste selection" now follows the rule, so by default it pastes the newest of your last OpsRemote selection and your last copy.
- **Titles with "&":** headings, tabs and cards use "&" instead of "and" (for example **Startup & exit**, **Security & vault**, **Data & backup**).
- **Inactive buttons look inactive:** buttons that cannot be clicked now have faded text in every look, Kvantum themes included (several dark themes drew them like active ones).
- **Clearer look buttons:** "Save into \"name\"…" is now **Save into Selected Look…** (one width whatever the name; the confirmation names the look), and "Back to \"name\"" is now **Revert Unsaved Changes**, with the look it goes back to in its tooltip. It now works after any change by hand and after a restart: the look the appearance came from is kept in the settings (`ui.base_look`), and at the first start the matching look is taken.
- **Interface font follows at once:** changing the interface font or its size in Preferences now updates every open window right away; some text (rows, buttons, lists under a style) used to keep the old size until the look was saved.
- **Copy on select works:** before, it never copied anything. It now copies once, when you finish selecting (mouse released, a word by double-click, a line by triple-click). It is on by default (like PuTTY), so every way of pasting gives the same text after a selection; see Mouse & clipboard below. A setting turned on by hand before stays on.
- **Edit before pasting:** the window that asks before several lines are pasted (or sent from the Commands tab) has **Edit the text**: change the text there, and what you edited is pasted. **Workspace → Mouse & clipboard → Start in editing mode** opens it editable every time.
- **Self-repairing program files:** no more "This copy of OpsRemote is incomplete" after an abrupt exit. The program's unpacked copy in `runtime/` now carries a list of its files, checked at each start. A copy that lost files (removing it was cut short, an antivirus or cleaner took some) is deleted and unpacked again on its own, in a few seconds; on Windows, while another OpsRemote still runs from it, only the missing files are filled in. Your sessions and settings are never in that folder.
- **One multi-line confirmation:** **Workspace → Mouse & clipboard → Confirm multi-line paste** now also covers commands of several lines sent from the Commands tab, which had a toggle of its own. It stays on unless you had turned off both.
- **Clearer start-up messages:** when OpsRemote really cannot start (its own package files are missing, the disk is full, its folder is read-only, Windows is too old), the message says what happened and why, that your sessions and settings are unaffected, and what to do.
- **One setting for links:** **Workspace → Mouse & clipboard → Links in terminal output**: open with Ctrl+click or the menu, from the menu only, or off. It replaces "Enable terminal links" and "Ctrl+click opens links"; your choice carries over.
- **Session name with user@host:** tabs can be titled "Session name (user@host)" (**Workspace → Tabs → Tab title**).
- **Padding applies at once:** changing the terminal padding updates open terminals, not only new ones.
- **Keyring works on newer Linux:** the system keyring (libsecret) failed to load on distributions newer than the package's base, such as Arch; OpsRemote now brings its own copy.
- **Reconnect settings for every type:** SSH, RDP and VNC each have Reconnect automatically, Wait before reconnecting and Tries (0 keeps trying) in their Preferences tab and in each session. RDP and VNC used to stop after 6 fixed tries.
- **Kerberos logon order:** **Security & vault → Kerberos → Sequence of authentication**: Kerberos first (as before), after keys, or last; sessions can choose their own.
- **Preview before copying passwords:** copying saved passwords between the vault and the system store first shows what is new, the same, or different; a different one is replaced only if you tick it. Passwords are never shown.
- **Incomplete proxy caught:** a proxy chosen without host or port is marked in red with the reason; Save waits until it is complete. Before, it silently connected without a proxy.
- **Choose the editor from a list:** **Network → Files & transfers → Editor** lists the text editors found on this computer, has Browse…, and says whether the program is there.
- **Clear inherited values:** in a session's settings, a row you changed gets a small ↺ button back to the inherited value (it can be turned off: **Appearance → Session list → Session settings windows**); its tooltip says "Revert to default". Fields show the inherited value as it is, without a "Default (…)" label, and drop-downs list it only once. In every session type's window and the folder's Kerberos tab.
- **One tab order for every session type:** Connection · Display or Appearance · Local resources · Automation · Network. RDP and VNC now open on Connection, and the serial line's tab is called Connection.
- **File-only SFTP and SCP sessions** no longer show terminal settings (Terminal type, Backspace, Forward X11, Files follow folder).
- **Local and container sessions** group their settings in General, Logon and Start cards; Logon only when there is something to log on with. User and Start folder say "As the distribution or image sets it" instead of "Default".
- **Proxy note** names the session's protocol (it said "SSH connections" for RDP, VNC and FTP too).
- **Settings updated automatically:** when a setting changes its place or form (as Copy on select did), OpsRemote converts your `settings.yaml` once, after backing up the settings folder (restorable in **Preferences → Data & backup**). A choice you made carries over; settings from a newer OpsRemote are left as they are.

## 0.6.1

- **Pasting several lines:** the confirmation (terminal paste and **Commands**) is a resizable window that shows the whole text in a fixed-width font, with its line count. It keeps its size until OpsRemote is closed.
- **Tabs with new output** are marked again with every look: before, the OpsRemote style and the Kvantum styles drew over the title's colour. The mark is now a softly pulsing dot beside the title (or a steady dot, or the title's colour, or off); each tab keeps room for it, so tabs do not move when one is marked. Its dot colour and pulse colour are Automatic (from the look, chosen to stand out against the tab bar) or Custom (**Preferences → Workspace → Tabs → Activity in background tabs**).

## 0.6.0

**Logging on**
- **SSH certificates:** a key's OpenSSH certificate (`key-cert.pub`) is sent with it, or a certificate chosen per session. The session window shows who it is for and until when, in red when it has expired or is for another user.
- **FIDO2 security keys** (`sk-ed25519`, `sk-ecdsa`; YubiKey, Windows Hello): logging on with a touch and, when the key needs it, its PIN. **Tools → SSH Keys** creates them (optionally kept on the key) and copies the keys kept on a security key.
- **Kerberos (GSSAPI)** on Linux: logging on with your domain ticket, optionally passing it on (`ssh -K`), for everything, a folder, or a session; Preferences show the ticket and run `kinit`.

**Automation**
- **Login scripts and triggers** (a session's or folder's **Automation** tab): wait for a text, then type an answer; watch the output and type, notify, beep, or mark the tab.
- **Saved scripts** (**Tools → Scripts**, kept in `settings/scripts/`): run whole on a server, in a tab, on many hosts, after logging on, or inside a container; with an interpreter, optional `sudo`, and `{fields}` asked for when they run.
- **Commands** and **Scripts** tabs beside Sessions and Files, with search and groups; **View** shows or hides each tab.

**New session types**
- **Local**: a shell of this computer (PowerShell, PowerShell 7, Command Prompt, Git Bash; bash, zsh, fish…) or any program, with **Run as administrator** (Windows UAC, Windows sudo; Linux sudo or pkexec).
- **WSL** (Windows): a chosen distribution, user and folder.
- **Container (Docker)**: a shell in a container, here, through a Docker context, on a remote engine over TCP with TLS, or on an SSH server; Podman too. **Open a Container…** on SSH sessions.
- **Container (Kubernetes)**: a shell in a pod, with the default kubeconfig, a saved credential, a kubeconfig file, a token, or a client certificate. **Tools → Kubernetes Credentials** keeps kubeconfigs encrypted or as private files.
- Their lists (distributions, containers, contexts, namespaces, pods) fill themselves, with their state on a line under each.

**Preferences**
- New categories: **Connections** has one tab per session type; **Network** (proxy, files and transfers), **Security and vault** (now with keys and certificates, Kerberos) and **Tools** (Run on hosts, HTTP requests, scripts).
- Every main feature can be turned off.
- Each session window opens on its protocol's own tab.

**Under the hood**
- libssh 0.12.2 in both packages (built from its signed release), with libfido2 and libcbor on Windows and MIT Kerberos on Linux.
